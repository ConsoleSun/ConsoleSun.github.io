让开发信拥有记忆:外贸智能体 v0.8.1,邮件归档与钉钉通知

发表于2026-08-04|更新于2026-08-06|技术
|浏览量:

这是系列第三篇。前两篇讲了整体框架和客户记忆系统,这篇讲 v0.8.1 的一次关键迭代:客户开发历史知识库(第 5 个 LightRAG)、邮件归档与域名映射、公司画像沉淀、钉钉获客通知。它回答一个真问题:如何让每一封开发信,都站在这个客户过去的所有往来之上。

一、这次迭代要解决的两个真问题

问题一:开发信不”认识”客户。 之前发开发信,靠的是模板 + 产品关键词 + 目标公司名称。但客户是有历史的——他回没回过信?回信里提过什么?我们给这家公司写过什么?这些信息散在收件箱和 ERP 里,起草时根本用不上。邮件没有记忆,开发信就只能是模板。

问题二:获客任务跑完了,没人知道。 全自动获客一跑就是几十分钟,发了几十封邮件——成功了、还是中途挂了,业务员不打开系统根本不知道。

v0.8.1 就干这两件事。

二、客户开发历史知识库:第 5 个 LightRAG 实例

系统原来有 4 个知识库(业务/技术/管理/开发信),这次加了第 5 个:客户开发历史(Port 9635)。

沉淀什么——每一次外发开发信,后台异步沉淀成档案:

  • 开发时间、我方开发信全文
  • 客户回信(IMAP 收到后按 from 域名匹配归档)
  • 公司画像(主营产品/行业/认证/规模/合作品牌)
  • 开发来源(国家 + 关键词)、负责业务员

起草时怎么用——三路 RAG 并行参考:

路由 查什么 给开发信什么
业务实力库 产品、产能、资质 我能做什么
开发信范例库 8000+ 封爆款话术 这封信该怎么写
历史客户库 这家客户/同类客户的过往往来 这封信该对他说什么

关键工程决策,逐个讲:

1. 域名映射做”邮件对关联”。 标准做法是用 Message-ID / In-Reply-To 把”我方开发信”和”客户回信”关联成一对。但现实是:外发邮件拿不到 Message-ID(现实约束)。所以用域名映射近似关联:发信时记录”发给哪个域名”,回信时按 from 域名匹配。同时把 In-Reply-To 存进收件箱,备未来升级。

在约束下找近似解,同时给精确解留好位置——这是生产环境里最常见的取舍。

2. 幂等插入三重保险。 归档是后台异步的,异步最怕重复。Redis 去重 + LightRAG 409 跳过 + track_status 轮询确认入库,三层防重。

3. 隐私隔离。 非获客客户的邮件不进库。 只归档”获客链路”里发出的和收到的邮件,不清洗客户的整个收件箱——这条边界,防的是把别人的隐私卷进自己的知识库。

三、钉钉通知:复杂任务转交的第一步

新增 agent/notify/dingtalk.py:

  • Webhook + HMAC-SHA256 加签(不是裸 Webhook,密钥用时间戳签名)
  • text / markdown 双格式,支持 @ 指定人
  • 获客任务完成 → 推送结果;获客任务异常终止 → 推送错误并 @all

但最有工程价值的是 _notify_safe 解耦:

通知模块任何故障——导入失败、方法缺失、网络异常、没配置——全部静默,绝不影响获客主流程。

配套 3 条解耦测试,专门验证”通知挂了,获客照跑”。外围功能可以坏,核心链路不能跟着死。

四、公司画像沉淀:让开发信真的”懂”客户

爬官网时顺带提取主营产品、行业、认证、规模、合作品牌,随补全缓存沉淀 7 天,写开发信时进【目标公司信息】段。

之前开发信是”模板 + 客户名”,现在是真的”知道你做什么、可能关心什么”。成本几乎为零(复用爬官网那一次请求),收益是每封信的个性化程度。

五、一个值得记录的取舍:并发 → 顺序

  • v0.7.2 为了提速,做了批量并发起草(每封 40s → 25s)
  • 但发现:批量起草共享 RAG 状态,导致邮件不参考 RAG——速度有了,质量塌了
  • v0.8.0 重构回逐家顺序流水线:关键词 → 谷歌 → 逐家官网补邮箱(失败跳过)→ 三路 RAG → 起草 → 发送 → ERP → 历史沉淀 → 下一家

先并发提速,再发现并发牺牲质量,回退顺序保质量。 这个取舍比”加并发”更难做——知道什么时候该拿掉并发,和知道什么时候加并发,是两种功力。

六、一个生产细节:LLM 容错解析

llm_parse.py:DeepSeek-v4-flash 是推理模型,max_tokens 会被”思考”token 吃光,输出经常被截断(finish_reason=length),JSON 不完整、带代码围栏、夹带说明文字。容错解析:去代码围栏 → 整串 loads → 回退最外层平衡花括号截取。

七、和”待更新项”的对账

待更新项 状态
全流程信息跟踪(存邮件) 已落地:第 5 个 LightRAG + 域名映射归档
全流程信息跟踪(图向量 + LLM 自动综合回复) 还差后半截(LightRAG 本身是图增强的,基础已备好)
复杂任务转交(钉钉通知) 通知通道已上线(目前覆盖获客任务完成/异常,客户意图触发待做)
Agent 自进化 未动

下一步:把”客户回信 → LLM 自动综合回复”接上,历史客户库就算真正闭环了;再把钉钉通知从”任务级”下沉到”客户意图级”——客户在对话里明确要找人,Agent 直接钉钉通知业务员。
