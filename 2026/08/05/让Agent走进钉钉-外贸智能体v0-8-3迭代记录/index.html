让 Agent 走进钉钉:外贸智能体 v0.8.3 双向指挥与写信叙事化

发表于2026-08-05|更新于2026-08-06|技术
|浏览量:

这是系列第五篇。这篇记 v0.8.2 和 v0.8.3 两件事:开发信从”列卖点”变成”讲叙事”,Agent 从”只能被系统页面调用”变成”能住进钉钉、被业务员直接指挥”。 一个让信更会说话,一个让 Agent 离人更近。

一、v0.8.2:让开发信”会说话”

外贸开发信之前有个老问题:模板感太强。卖点是”分点列出”,读起来像产品说明书,不像一封来自有血有肉销售的信。

v0.8.2 把写信提示词整个改掉,从”分点列卖点”改成高转化率销售顾问叙事:

  • 开头贴合对方业务建立共鸣——第一段先讲对方的处境,而不是先讲自己
  • 卖点融进句子——不堆砌 bullet,把优势织进叙述里
  • 挑 2-3 个最有说服力的数据——不贪多,用数字说话

配套的几个工程细节:

1. 公司硬实力恒在,不依赖 RAG。 新增 CAMPAIGN_COMPANY_FACTS 常量——公司的主营、产能、认证等硬实力写死在配置里。这样即使 RAG 检索失败,信里依然有卖点,不会因为一次检索失败就退回空洞模板。

2. 落款在代码层完整附加。 姓名/职位、公司全称、邮箱、电话+WhatsApp、网址——5 行标准名片,代码统一拼接。不依赖模型”记得”加落款,不受目标语言商务信习惯影响。

3. RAG 查询拼入公司名+国家。 每家公司的检索词都带上它自己的名字和国家,让检索结果差异化,而不是所有信共用同一批模板语料。

验证方式也很直接:真实日语客户的一轮实测——个性化共鸣开头 + 公司叙事 + 数字卖点 + 完整落款,整体质量与手动获客对齐。

二、v0.8.3:让 Agent 住进钉钉

这是这一版的主角:Agent 第一次能被”外面的人”直接指挥——业务员在钉钉群里 @它,它就能干活,并把结果推回来。

反向指挥:钉钉 HTTP Callback 的处理

钉钉的 Callback 有个硬约束:必须在 5 秒内返回,否则超时。 而一次完整的 Agent 调用显然远超 5 秒。

解法是异步解耦:

回调方永远不会等 Agent 算完——秒回确认,后台慢慢跑,结果异步推。这个”先应答、后处理、再推送”的模式,是接入任何带超时限制的外部回调的通用解法。

身份绑定:让钉钉里的人 = 系统里的人

Agent 在钉钉里干活,前提是知道你是谁、你有什么权限。v0.8.3 加了身份关联:

  • users 表补全 dingtalk_staff_id、bind_code、bind_code_expires_at 字段和索引
  • 员工在钉钉里发”绑定 绑定码“→ 关联到系统账号(绑定码 6 位、15 分钟有效)
  • 绑定后,钉钉里的指令继承他的 Role、权限、个人发信 SMTP 账号
  • 发”解绑”可清除绑定

这个设计的价值在于:Agent 在钉钉里是以”某个具体的员工”的身份在工作——用他的权限、他的发件邮箱。它不是凌驾于人之上的自动机,而是那个员工名下的助手。

主动推送:Agent 也能找上门

反过来,Agent 在会话里可以主动向钉钉群上报消息。新增 send_dingtalk_notify 工具(staff/admin):

  • info / warn / error 三级告警
  • error 级别可 @all
  • 推送失败不抛异常、不影响主流程——延续了”外围功能可以坏,核心链路不能跟着死”的纪律

机器人身份统一

主动推送优先走 Stream 应用机器人(robot/groupMessages/send,和 @Agent 是同一个身份);不可用、目标群未缓存、发送失败时,自动回退自定义机器人 Webhook 并 @all。收到群 @消息时自动缓存 openConversationId,也可以手动指定目标群。

一个机器人、两种通道、自动回退——身份统一,链路兜底。

质量保障

新增 test_dingtalk_bot.py(18 条)和 test_dingtalk.py(21 条,覆盖 Stream 优先/回退链路),630 条单元测试 100% 全过。

三、一点反思:技术解决”能不能用”,不解决”想不想用”

这两版解决了”能不能用”:信更好写了,Agent 能被钉钉里的人指挥了。但一个更朴素的事实摆在那里——一个工具技术上完整,不等于有人用它。

这里有个值得说的工程认知:“能用”和”会被用”之间,隔着一个和代码无关的鸿沟。 决定一个内部工具命运的,往往不是它的架构,而是使用者愿不愿意在每天的流程里为它腾出一个位置。技术能做的,是把工具做得足够好用、足够省力、足够贴近使用者已有的习惯——比如让 Agent 住进钉钉,而不是要求使用者记住一个新系统。但”被接受”这件事,最终要靠数字证明,靠一个人先用起来、其他人看到结果。

结语

v0.8.2 和 v0.8.3 合起来看,是一条很清楚的线:把 Agent 从”系统的工具”变成”人的助手”——信更有人的味道,入口更贴近人的习惯,身份更归属于具体的人。

技术的下半场,拼的不是能力边界,而是它能不能以人习惯的方式,站到人身边。
