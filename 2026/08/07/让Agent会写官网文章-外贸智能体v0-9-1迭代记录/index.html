让 Agent 会写官网文章:外贸智能体 v0.9.1 迭代记录

发表于2026-08-07|更新于2026-08-09|技术
|浏览量:

这是系列第七篇。上一篇《把屎山推倒的那天》讲了 v0.9.0 如何还债、拆结构。这一篇讲 v0.9.1——三个看起来不搭界的改动凑成一版:让 Agent 会写官网文章、让工具调用经得起截断、让真实凭据不再进代码库。三个改动,对应三个方向:能力、稳定、底线。

一、Agent 开始写官网文章

公司的官网需要持续产出 B2B 文章来撑 SEO。以前这条产线是纯人力的:业务员想选题、查资料、写正文,还得自己排版——把 Markdown 手工改成一堆 inline CSS 的 HTML,再登录 WordPress 后台粘贴发布。写文章本身不难,难在”会写又会排又会发”。

v0.9.1 把这条产线交给 Agent。设计上最核心的一个决定是:把排版从 LLM 手里拿走。

LLM 能写出好内容,但让它在正文里手动拼 <div style="..."> 这种内联样式,既容易错又难维护。而”把 Markdown 编译成公司设计系统的 HTML”是个确定性任务——确定性任务不该让大模型去做,该让代码做。

于是有了 compile_b2b_markdown_to_html:LLM 只负责输出干净的英文 Markdown,后台编译器按 b2b-style-kit v1.3 设计系统自动生成:

  • 自动提取 ## 标题,生成带锚点的目录卡片(TOC)
  • Markdown 表格 → 棕色表头的专业对比表格
  • 图片按布局规则处理:竖图必须左右混排(Layout A/B,一侧 220px 图、一侧段落文字,多张一左一右交替),只有横图才允许整幅居中
  • 文末自动拼接 CTA 询盘区块
  • 默认打入分类 ID 22(Industry News),发布状态默认 draft

配套 5 个工具,全部 staff/admin 专用:

工具 作用
publish_wp_article 撰写 + 编译 + 发布(默认草稿)
update_wp_article 合并更新已有文章
delete_wp_article 删除(内置防误删纪律)
upload_wp_media 传图到媒体库
search_wp_posts 检索站内已有文章,做内链去重 + SEO 内链

写作硬性要求直接写进了员工 prompt:全文严禁 Emoji、严禁 ** 加粗、竖图必须 ![Alt | left/right](URL) 左右混排。这些规则不是提示词技巧,是和设计系统对齐的约束——LLM 在生成时就带上排版约束,编译器才能产出符合规范的页面。

到这里,Agent 的”输出口”已经有三条:写信(开发信)、发帖(Facebook)、写官网文章(WordPress)。前两个是短周期沟通,官网文章是长周期资产——它会一直在搜索结果里被找到,持续给公司带来询盘。

二、给工具调用装上防截断

这一版没有新功能的一侧,是一个反复咬人的老问题:DeepSeek 是推理模型,thinking tokens 经常把 max_tokens 吃满,工具参数的 JSON 在中间被截断,json.loads 直接抛异常,这一轮工具调用就废了。

以前的处理是抛错让 LLM 重试,但重试往往还是截断——问题没有根治。

这次在 loop.py 里加了一个 _safe_parse_json_args,五层容错:

  1. 非严格解析(strict=False,容忍不合法但可读的 JSON)
  2. 清理换行与控制字符再解析
  3. 自动补全末尾未闭合的引号和括号(截断修复——最常用的一层)
  4. 正则抽取已完成的键值对字段(保底防崩溃)
  5. arguments 嵌套解包

同时把 LLM 超时从 45s 提到 120s、LLM_MAX_TOKENS 默认从 4096 提到 8192——给推理模型留出思考空间。

网关层也补了两个容错:参数被 LLM 包成 {"arguments": "..."} 时自动解包;只把函数签名允许的参数传给工具(之前可能因为多余参数抛 TypeError)。工具签名里声明 session_id / user_profile 的,网关自动注入——工具不用再从请求体里偷上下文。

三、真实凭据不进代码库

这一版差点踩一个老坑:WordPress 应用密码——生产站 admin 的写权限——一度躺在 .env.example 里,还硬编码在 config.py 的默认值里。更要命的是明文和 base64 解码出来对不上,说明是手抄的、还抄错了一处。

好在这次在提交前查出来了,真实密码从没进过 git 历史。处理是:

  • .env.example / config.py / README 一律换成占位符
  • 真实值只在 gitignored 的 .env
  • 顺带把 WP REST API 硬编码的 verify=False 改成 WP_VERIFY_TLS 默认 true——Basic 认证走不校验 TLS 的连接,等于把密码明文发给可能被劫持的通道

上一篇说过一句话:”真实凭据不进代码库,是底线。”这一版差点自己破了这条底线。

凭据不是配置,是秘密。秘密只能有一个家:开发者的 .env,不能进仓库。

四、数字

  • 工具注册表:18 → 23(新增 5 个 WP 工具;customer 5 个不变,staff/admin 23 个全量)
  • 测试:765 → 773(新增 test_wp_publish.py 8 条)
  • 新增 5 个工具全部走同一条网关管线,自动获得熔断、权限、校验、失败修正——上一篇说的设计红利,这次又兑现了一次

结语

v0.9.1 三个改动,三个方向:能力(Agent 会写官网文章)、稳定(工具调用不再随机截断)、底线(真实凭据不进门)。

回到系列第一篇那句话:LLM 是大脑、上下文是眼睛、工具是手脚。这一版,手脚又长了一双——而且这次不是”动手”(执行),是”写作”。Agent 从只会回消息、写信、发帖,到会产出长周期的官网内容资产。能力在往外扩,但地基稳不稳,还得看下一版。
