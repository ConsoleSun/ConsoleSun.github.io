配图的边界,图纸的真相:两个图像闭环思路的验证

发表于2026-08-13|更新于2026-08-13|技术
|浏览量:

这是系列第十二篇,也是第一篇没有”迭代记录”的文章——因为今天项目上没有大更新,我在验证两个新思路。一个往外:给 SEO 文章配图,不再需要人读文章找图;一个往里:让公司的图纸变成可搜索的资产。两个思路一进一出,都是图像闭环,都卡在一个点上,也都在往同一个方向解。

一、思路一:SEO 文章配图,不再需要人读文章选图

1. 痛点

v0.9.1 让 Agent 会写官网文章之后,产线还剩下一个手工环节:配图。文章写完,得有人通读全文、理解核心段落讲什么、去素材里找一张合适的图。文章是自动的,配图是人工的——这条产线就没全自动。

思路很直接:让 Agent 自己配图。

2. 方案:3 个 LLM 交叉融合

文章生成后,链路是这样走的:

三个 LLM 各司其职:纯文本强力模型负责写提示词(把”核心含义”翻译成”可生图的提示词”),生图模型负责把提示词变成图,多模态模型负责审批——按提示词给图评分,高于阈值放行,低于阈值带着强调意见打回重生。连续失败 3 次,流程判失败,钉钉通知艾特负责人。

为什么要 3 个模型交叉?因为生图是不确定性的重灾区:同样的提示词,生出来的图千差万别,而且”好”与”不好”是主观判断。主观判断不能靠一个模型拍板,要靠另一个模型审批——给生成的不确定性套上质检环。这是我做这个系统以来一直在做的事:工具网关、滚动摘要、风格令牌,都是给不确定性套边界。这一次,轮到图像了。

3. 两个讨论过的细节

失败阶梯要升级,不是原地打转。 一开始的循环是”审批打回 → 带强调重生”,但这里有个坑:同一提示词下反复强调重生,撞墙的变量只有生图模型;如果病根在提示词本身(太抽象、不可生图化),重生一万次也过不了阈值,等于烧了几次生图成本才知道是提示词不行。所以改成每级失败换一个变量:

  • 失败 1 次 → 审批意见打回重生(变量:生图模型)
  • 失败 2 次 → 审批意见连同原图退回纯文本模型,重写提示词再走一遍(变量:提示词)
  • 失败 3 次 → 钉钉艾特负责人(流程级兜底)

审批的评分阈值要校准,不能拍脑袋。 多模态模型说”图和提示词匹配”,不代表它真的匹配——它也会幻觉、也会审美跑偏。上线前先做小样本校准:拿 20-30 张生成图,人工打分和模型打分对照,看它是不是系统性放水(普遍虚高)或过严,再定阈值。另外审批要拆两个维度:图-提示词匹配度、品牌调性——把公司设计风格写进审批提示词,不然会出现”图很美但和官网风格不搭”的通过案例。

二、思路二:图纸生图,让图纸变成可搜索的资产

1. 痛点

公司有大量图纸——玻璃瓶的设计图纸,尺寸、容量、形状全在上面。但图纸是死的:躺在文件夹里,客户拿一张产品照片来问”有没有这样的瓶子”,业务员没法拿图纸去搜,图纸之间也没法比。图纸是资产,但它是不可搜索的资产。

2. 方案:图纸 → 生图 → 向量库

图纸信息按字段存,图片转向量——这样客户拿实物照片来,能搜到最接近的产品效果图,连带返回它的图纸数据。图纸从”死的档案”变成”活的检索入口”。

3. 卡点:瓶身识别和标注线打架

验证卡在了第一步:提取图纸信息。本地多模态模型无法准确判断图纸中瓶子的形状——瓶身的轮廓线和尺寸标注线混在一起,模型分不清。试了 OpenCV 轮廓提取,效果不显著。

这里要诚实记录一个判断:卡点在预期内。图纸是稀疏语义图(线条、标注、虚线),本地小模型的视觉编码器对”细线条 + 稀疏信息”的理解能力天生弱,在自然照片上还能看,在工程图上就是瞎猜。换更强的模型只能缓解,不能根治。

但更重要的是,复盘时发现:这个问题根本不该在像素层解决。

4. 解法方向:图纸是 PDF,矢量层里本来就能分开

OpenCV 效果不显著是必然的:图纸渲染成位图那一刻,标注线和瓶身线都变成了一样的黑线,信息已经混死,像素层再怎么调参都拆不开。但 PDF 是矢量的,标注线和瓶身线在矢量层本来就是分开的对象。三层先验,按易到难:

  1. 颜色:CAD 导出 PDF 时,标注层和轮廓层往往不同色(标注红/蓝,轮廓黑)——分色就分开了,不用识别
  2. 几何:标注线是直线(尺寸线、延伸线、引线),瓶身轮廓是曲线(肩部弧线、瓶身曲线)——按曲线/直线分类,瓶身曲线簇直接落袋
  3. 文字关联:标注线永远紧挨着尺寸数字——文字坐标和线段的 bbox 做空间关联,紧邻文字、成对平行、端头带箭头的直线群就是标注,删掉

这套全是确定性几何判断,不需要模型参与,拿到的瓶身参数是精确的数学事实(高宽比、肩部曲率、瓶颈位置),不是模型”猜”的。

还有个判断值得记下来:上顶尖多模态模型,不解决”标注线打架”——它读的也是渲染后的像素,干扰依旧。正确顺序是:矢量层分离,拿干净的瓶身轮廓,再决定要不要模型——分离成功,参数就是精确的;就算还想让模型做语义分类(圆肩/方肩),喂它干净轮廓图的准确率也比喂原图高一大截。矢量分离是两条路的共同第一站,而且成本是零。

三、两条思路的共同点:图像进出系统,都要过一道”确定的门”

回头看,两个思路是同一个哲学在图像上的两面:

  • 思路一是向外给:配图是给读者看的东西,给出去之前要过一道质检环——图生成之后由多模态审批,把”这张图行不行”的主观判断,放进一个可迭代、有熔断、有人兜底的边界
  • 思路二是往里增:图纸是公司的存量资产,要进向量库先得变干净——图理解之前过矢量分离,把”这张图纸是什么形状”的确定性任务,从模型手里拿走,交给几何事实

向外给的,要套上边界;往里增的,要先拿到真相。这套系统对文字做过的事(工具网关、滚动摘要、风格令牌、先落盘再遗忘),现在轮到图像:模型可以生成,但生成的图要过审批;模型可以理解,但理解的输入要先变成干净的数学。

诚实的部分

  • 两个思路都还在验证阶段,一篇都没有落地:思路一的阈值没校准,思路二卡在读图纸
  • 思路二为了验证加班了两个小时,最后卡在”本地多模态读不准图纸”——但复盘后的结论是,卡点本身提示了正确的解法方向
  • 思路二能不能成,取决于矢量分离的效果,明天用真实图纸验证

结语

回到系列第一篇:LLM 是大脑、上下文是眼睛、工具是手脚。今天这两个思路,都在打磨”眼睛”的进与出——配图是眼睛的输出,图纸是眼睛的输入。

给不确定性套上可信边界,是这个系统从头到尾在做的事。以前边界套在文字上,今天发现图像也一样:生成要过审批,理解要先分离。模型的想象力不该被压缩,但它的输出和输入,都值得一道确定的门。
