名片落袋,开口三思:发信纪律与线索资产

发表于2026-08-18|更新于2026-08-18|技术
|浏览量:

这是系列第十四篇。第十三篇讲了"找人"——多渠道获客、决策人挖掘、Apollo 放行。这一篇讲"发信",或者说,讲 Agent 在开口之前学会的三件事:把名片收好(线索资产)、把重复的话咽回去(发信防重)、把该查的资料查完(前置拦截)。外加一条铁律:没确认做成的事,不许说做成了。

一、名片要落袋:线索资产化

获客产出的线索,以前住在哪?住在会话里、住在 data/exports 的 JSON 文件里。散、不统一、查不了:发过开发信的公司和没发过的混在一起,同一个公司被两个渠道各挖一次,数据就重复了。

这一批给线索建了一个家:PostgreSQL 的 crm_leads 表(lead_store.py)。公司名、域名、邮箱列表、电话列表、WhatsApp、LinkedIn、Facebook、地址、城市、国家、分类、评分、评价数、主联系人、决策人列表、来源渠道、触达状态——一张表全部落袋。域名建唯一索引;没有域名的,按(标准化企业名, 国家)匹配。

落袋的规矩是智能合并,绝不覆盖:已存在的企业,只追加新增的邮箱、电话、决策人名单,评分取最高——已有的触达历史(sent_count / last_contacted_at / last_sent_subject / last_sent_by)一根毫毛都不动。

同时维护全局线索池 JSON 镜像(global_leads_pool.json),异步同步,失败只记日志、不阻断获客主流程;启动时自动导入历史存量获客文件,新老线索统一口径。数据层提供 get_crm_leads 按国家/分类/状态检索——先落袋,后面要用随时查。

二、开口三思:发信防重

给同一家公司发两次一模一样的开发信,会发生什么?客户第一反应是拉黑,第二反应是投诉——企业域名的信誉就毁了。以前这件事靠人记:业务员多了,张三开发过的公司,李四不知道,又发一遍。

现在发信前自动过 check_outreach_duplicate,三维查重:

  • 收件邮箱精准匹配:这个邮箱触达过,拦
  • 公司主域名匹配:发过 info@brand.com,再发 sales@brand.com——同一家公司,拦(免费邮箱域名除外,gmail/outlook/yahoo/hotmail 不参与域名维,只能靠邮箱维)
  • 标准化企业名匹配:同国家同名公司,拦

内部测试邮箱(@qq.com / @163.com / @126.com / @vitglassbottle.com)白名单免检。拦截时给出完整上下文:谁在什么时候、以什么主题、累计发过几封——并提示跟进信可以 force=True 放行;"跟进/追信/follow up/强制发送"这些词会被自动识别为明确跟进意图。

发送成功后 mark_outreach_sent 实时记账;如果这家公司此前没录入,自动补建一条"已触达线索"。账本永远比记忆可靠。

三、开口之前,先查知识库

第七篇《让 Agent 会写官网文章》里立过一条规矩:发开发信之前,必须先查开发信知识库(8000+ 封一线爆款邮件模板)——那时候是提示词层面的要求,LLM 可能"忘了查"。

这一版把它变成硬拦截:send_email 工具描述和执行时校验双重声明,未先调用 search_outreach 直接拒绝发送。纪律从"靠自觉"变成"靠结构"——和风格令牌化同一个哲学:不给 LLM 犯错的机会,约束的是接口,不是想象力。

四、只给看得见的工具

这一批还修了一个线上事故。一位工具权限被清空的员工,被员工提示词里硬编码的"可访问全部工具"误导,Agent 开始叙述式编造:✅邮件已发送、✅已查收件箱——实际上什么都没发生。对业务系统来说,编造执行结果比执行失败可怕得多:失败可以重试,编造会让人做出错误决策。

修复分三层:

  • 删掉提示词里硬编码的工具清单,工具描述只按实际权限注入"可用工具"区——LLM 看到的工具,就是它真的能用的工具
  • 空权限明确写明:"你当前没有任何可用工具……绝对禁止假装执行或编造结果"
  • 新增 ACTION_HONESTY_RULE 铁律:未收到工具执行确认,禁止声称动作完成;工具不可用必须明说

这修的不只是一个 bug,是对信任模型的修正:模型默认会顺着提示词"演戏",唯一可靠的证据是工具的真实返回。

五、数字

  • crm_leads 表:一张表收下公司/联系方式/决策人/触达状态全量字段,域名唯一索引
  • 查重维度:3(邮箱 / 主域名 / 标准化企业名)+ 白名单免检 4 个后缀
  • 工具注册表:25 个(23 内置 + 2 Apollo)
  • 测试:792 收集(默认套件 783 条全绿 + 9 条真实环境 integration 默认排除)

六、诚实的部分

  • 企业名标准化是枚举规则(inc/ltd/gmbh/sarl/pty…),新后缀、新语言的公司名要持续补
  • 防重是发信前的拦截,但"发过但没落库"的存量(比如历史手动发的邮件)补不进来,账本从接入那天开始记
  • 前置拦截校验的是"查没查过知识库",不是"查得好不好"——质量还得靠 RAG 检索效果本身
  • get_crm_leads 目前是数据层能力,员工侧的检索工具化还在路上
  • 这一批都还在 dev 分支,稳定后会合并 main 发版

结语

回到系列第一篇:LLM 是大脑、上下文是眼睛、工具是手脚。这一版动的是手脚的"分寸感":什么话可以开口、什么话要咽回去、开口前要先做什么、没做成的事怎么如实说。

外贸是关系生意,关系的起点是第一次接触。第一次接触的体面,靠的就是这三件事:名片落袋,开口三思,说过的话有据可查。给不确定性套上可信边界——防重是给客户套边界(不被骚扰),前置是给质量套边界(不裸发),诚实铁律是给信任套边界(不演戏)。Agent 越来越像一个靠谱的业务员了。
